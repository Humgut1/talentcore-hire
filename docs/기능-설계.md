## 0. 설계 전제

| 전제 | 내용 |
|---|---|
| 자동화 범위 | 슬롯 탐색 · 알림 · 리마인더 · 상태 기록 · 캘린더 인비 발송 |
| 사람 범위 | 예외 협상 · 임원(EA) 조율 · 최종 판단 · 관계 관리 |
| 확정 조건 | AI는 일정을 **확정하지 않는다.** 면접관의 명시적 클릭이 있어야 확정 |
| 색 사용 | 앱 전체에서 **색은 상태에만** 쓴다. 버튼·강조는 무채색 |
| 외부 사용자 | 후보자·면접관은 계정을 만들지 않는다 (서명 링크 / Slack) |

### 상태 4색 (전 화면 공통)

| 상태 | 색 | 의미 | 사용자 행동 |
|---|---|---|---|
| AI 진행 중 | `#9A9AA5` 그레이 | 자동 처리 중 | 볼 필요 없음 |
| 사람 대기 | `#D92D20` 버밀리언 | 에스컬레이션 발생 | **지금 처리** |
| 지연 | `#B5730B` 앰버 | 기준 시간 초과 | 곧 처리 |
| 완료 | `#0A9459` 그린 | 단계 확정 | 없음 |

> **'AI 진행 중'은 회색이다.** 초기안은 인디고였으나, 그 상태의 의미가 "볼 필요 없음"인 이상
> 시선을 끄는 색을 줄 이유가 없다. 회색으로 내리면 화면에서 색이 붙은 것 = 사람이 볼 것이 되고,
> 동시에 인디고를 브랜드 액센트로 되찾을 수 있다.

### 브랜드 · 단계 색

| 용도 | 색 | 쓰이는 곳 |
|---|---|---|
| 브랜드 | `#5B53D6` → `#4A43BD` 인디고 | 로고 마크, 활성 내비, 강조 아이콘 |
| 단계 램프 | `#C3C5E2` → `#5B53D6` | 전형 단계 표식(지원 접수 → 오퍼). 진행될수록 브랜드에 수렴 |

단계 램프는 인디고 계열, 상태는 적/황/녹/회 — **색상 계열이 겹치지 않으므로 한 화면에 같이 있어도 서로를 오염시키지 않는다.**

## 2. C-3 공고별 파이프라인 — 이 제품의 중심 화면

### 이 화면이 답해야 할 질문 (우선순위 순)

1. **지금 내가 손대야 할 후보자는 누구인가**
2. 각 후보자는 어느 단계에서 며칠째 머무르고 있는가
3. 이 공고는 어느 단계에서 막히고 있는가
4. 다음 행동은 무엇이고, 몇 번 클릭에 끝나는가

### 설계 규칙

| 규칙 | 이유 |
|---|---|
| 카드에 문장을 쓰지 않는다 | 이름·경과일·상태색만으로 판단이 서야 한다. 예외일 때만 4~6자 사유를 붙인다 |
| 색은 상태에만 쓴다 | 버튼·헤더·아바타가 색을 쓰면 빨강 하나가 안 보인다 |
| 킥오프·디브리프는 열이 아니다 | 후보자 단계가 아니라 **공고 단위 미팅**이다. 상단 스트립으로 분리 |
| 기본 정렬은 위험도 순 | 사람 대기 → 지연 → AI 진행 → 완료 |
| AI 진행 중은 접을 수 있어야 한다 | 볼 필요 없는 것이 화면의 대부분을 차지하면 안 된다 |

### 후보자 단계 (6)
`지원 접수 → 서류 검토 → 1차 인터뷰 → 2차 인터뷰 → 오퍼 → 입사`

### 공고 단위 미팅 (2)
`킥오프` (1차 최초 합격자 발생 시) · `디브리프` (2차 완료자 발생 시, 공고당 1회 통합)

#### 레퍼런스 근거 (Lazyweb 실제 제품 화면)

| 차용한 패턴 | 출처 화면 | 적용 |
|---|---|---|
| 상단 가로 단계 레일 + 인라인 카운트 | 채용 관리 제품의 후보자 목록 화면 | 시안 B 상단 레일 |
| 저채도 칸반 — 열 머리(점·이름·수), 카드 우측 경과일 칩, **열 발치 집계행** | CRM 딜 파이프라인 보드 | 시안 A 카드·열 발치 평균 체류 |

| 처리 대기만 위로 올리는 트리아지 인박스 | 이슈 트리아지 큐 | 시안 C |

> 실제 화면 캡처를 직접 확인해 검증한 패턴만 반영했습니다. 브랜드명은 외부 공개물에서 제외합니다.

| 시안 | 관리 은유 | 강점 | 약점 |
|---|---|---|---|
| **A. 스테이지 보드** | 공간 — 단계별 적체를 부피로 본다 | 익숙함, 드래그 이동, 적체가 즉시 보임 | 조율 상태가 카드 안에 갇힘. 세로 스크롤이 길어지면 위험 신호를 놓침 |
| **B. 진행 레일** | 궤적 — 후보자×단계 매트릭스 | 개인 진행과 공고 병목을 동시에. 정보 밀도 최고 | 후보자 수가 많아지면 스크롤. 신규 지원자 대량 유입에 약함 |
| **C. 트리아지** | 우선순위 — 할 일 큐 | 글자·클릭 최소. "오늘 할 일 0건"이 목표가 됨 | 파이프라인 전체 조망이 약해 리크루터에게는 부족 |

### 권장

**A를 기본으로, C를 코디네이터 홈(B-1)으로 분리**하는 조합을 권합니다.
B의 매트릭스는 공고 상세 안의 **보조 뷰(진행 탭)** 로 두면, 리크루터가 병목을 볼 때만 꺼내 쓰게 됩니다.
세 개를 한 화면의 뷰 전환 토글로 넣는 것도 가능하지만, 그 경우 **기본값은 A**여야 합니다.

### 드래그 = 단계 이동 = 자동화 트리거

카드를 옆 열로 끌면 단계가 바뀌고, **그 단계의 종류(`kind`)에 따라 다음 자동화가 즉시 시작**됩니다.

| 이동한 단계 | 일어나는 일 |
|---|---|
| 서류 검토 | HM에게 검토 요청 발송 → `AI 진행 중` |
| 인터뷰 | 설정된 길이(60/120분)로 캘린더 교집합 탐색 시작 |
| 인터뷰 — **면접관에 EA 조율 대상 포함** | **자동화 제외 → 즉시 `사람 대기`, 코디네이터 라우팅** |
| 오퍼 | 오퍼 승인 대기 |
| 불합격 | 통보 메일 **초안만** 생성 (자동 발송 없음) |

모든 이동은 토스트의 **되돌리기**로 6초간 취소할 수 있습니다.

### 전형 단계 커스터마이즈 (C-2)

공고마다 단계를 다르게 둡니다. 여기서 만든 단계가 **그대로 보드의 열**이 됩니다.

- 이름 인라인 수정 · 드래그로 순서 변경 · 삭제
- 단계별 **기준 체류일(SLA)** — 초과하면 카드가 주황(지연)으로 바뀜
- 인터뷰 단계는 **면접 길이(30~120분)** 지정 — 교집합 탐색 블록 길이가 됨
- 프리셋: 사전 과제 · 컬처핏 인터뷰 · 실무 인터뷰 · 레퍼런스 체크 · 임원 면접 · 처우 협의
- **진행 중인 후보자가 있는 단계는 삭제 불가** (경고 토스트)
- **입사 · 불합격은 고정 단계** — 이름·순서 변경 불가
- 단계를 추가하면 Export 타임스탬프 컬럼이 자동으로 늘어남

## 5. 면접관 화면 (2026-08-27)

### 원칙 — 면접관은 ATS에 로그인하지 않는다

기획서의 핵심 규칙은 **"AI는 일정을 확정하지 않는다. 면접관의 명시적 클릭이 있어야 확정된다"** 이다.
그 클릭이 일어나는 장소가 ATS 내부라면 규칙 자체가 성립하지 않는다. 본부장·CTO는 로그인하지 않기 때문이다.
따라서 면접관 쪽은 **앱이 아니라 링크 4장**으로 설계한다.

| # | 화면 | 형태 | 발송 시점 | 목표 지표 |
|---|---|---|---|---|
| ① | 슬롯 선택 카드 | Slack DM / 메일 본문 | 교집합 탐색 직후 | **응답률** |
| ② | 면접 브리핑 | 토큰 링크 (로그인 없음) | 면접 하루 전 | 면접 품질 |
| ③ | 평가 제출 | 토큰 링크 | 면접 종료 직후 | **제출률** |
| ④ | 내 면접 · 가용시간 | 로그인 (유일) | 상시 | 제안 정확도 |

①③은 응답률이 목표이므로 정보를 깎는다. ②는 면접 품질이 목표이므로 밀도를 올린다.
설계 원칙이 서로 반대이므로 같은 템플릿을 쓰지 않는다.

### "AI는 확정하지 않는다"의 실제 의미

**AI가 하는 일** — 면접관 캘린더에서 단계별 길이(1차 60분 / 2차 120분 연속)의 빈 블록 탐색,
버퍼·업무시간·타임존 적용, 겹치는 시간 3개 추출, 발송, 미응답 리마인드, SLA 초과 시 에스컬레이션.

**AI가 하지 않는 일** — 확정. 이유는 셋이다.

1. **캘린더 빈칸 ≠ 가용 시간.** 이동·준비 시간, 비공개 일정, 그날의 사정은 캘린더에 없다.
2. **틀리면 후보자가 비용을 문다.** 재조율 통보는 후보 이탈 사유 상위권이다.
3. **한 번 어긋나면 연동을 끈다.** 면접관이 캘린더 연동을 끄면 자동화 전체가 죽는다.

그래서 **제안까지 AI, 확정은 사람**. 대신 확정에 드는 마찰을 **클릭 한 번**으로 줄인다.
같은 이유로 후보자에게도 면접관 확정 전에는 아무 것도 발송하지 않는다.

### 화면별 결정 사항

**① 슬롯 선택 카드**
- 슬롯 3개 + `세 개 다 어렵습니다` + `이력서 보기`. 그 외 아무 것도 넣지 않는다.
- 확정 시 → 캘린더 인비 / 다른 면접관 동시 발송 / 화상 링크 자동 생성 / 후보자 안내. 4줄로 결과를 명시한다.
- 거절 시 → 탐색 범위 10 → 15 영업일 확대, 상대 면접관 재확인, 24h 내 실패 시 코디네이터 인계.
  **후보자에게는 이 과정이 보이지 않는다.**
- **EA 조율 대상(한도경·윤태경)에게는 이 카드가 아예 발송되지 않는다.** 즉시 코디네이터 라우팅. (규칙 R6)

**② 면접 브리핑**
- 1회용 토큰 링크. 평가 제출 후 7일 만료(개인정보 보유 기간과 연동). 열람은 감사 로그에 기록.
- 확인할 항목 4개에 각각 **무엇을 캐물을지 한 줄 가이드**를 붙인다. 이력서 링크만 던지면 아무도 보지 않는다.
- 하단 `참석이 어렵습니다`는 확정 후에도 살아 있다. 취소를 어렵게 만들면 노쇼가 나고, 노쇼가 재조율보다 비싸다.

**③ 평가 제출**
- 좌 이력 / 우 스코어카드 고정. 창을 옮겨 다니며 쓰지 않는다.
- 4항목 전부 + 결과 선택 전까지 제출 버튼 비활성.
- **다른 면접관 점수는 내 제출 전까지 가린다.** 앵커링이 생기면 점수가 수렴하고, 이견 없는 디브리프는 열 이유가 없다.
- 제출 = 단계 이동. 칸반 드래그와 **같은 이벤트**다. Pass → 2차 슬롯 탐색 즉시 시작.
- 미제출 48h → 규칙 R4 에스컬레이션.

**④ 내 면접 · 가용시간**
- 주간 가용시간 그리드(월–금 × 10–18시). **끈 시간에는 슬롯 제안이 가지 않는다.**
  캘린더 일정(빗금)은 조정 불가.
- 주당·일당 최대 면접 수를 면접관 본인이 쥔다. 면접 과부하는 조용히 응답률로 나타난다.
- EA 조율 토글은 **본인이 켤 수 없다.** HR이 사람 단위로 설정하며 직급으로 자동 판단하지 않는다.
